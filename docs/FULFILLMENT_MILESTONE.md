# Paid production and private final delivery

The manual payment milestone passed source, database and three-engine browser suites. Existing schema 004 was successfully applied on Hostinger. This milestone implements explicit paid-order transitions (awaiting arrangement → in progress → ready for delivery, with return to production), followed by one final WebP release. The request and order become completed atomically with the deliverable record. No provider call, money movement, email, automatic portfolio publication or customer-visible draft occurs. Existing approved-policy and order gates plus independent disabled-by-default delivery approval and release switches apply. A paid flag alone is insufficient: full manually verified payment matching the accepted quote is required. The customer download endpoint rechecks ownership, completed state, matching payment evidence and file checksum on each request. Released files cannot be removed via draft management. Pausing delivery release also pauses downloads. No automated dispute/refund or post-release revisions, partial deliveries, lossless originals or access-duration policy are implemented. These require owner decisions before launch. CI exercises synthetic payment evidence and the entire release lifecycle without contacting a payment provider. Production switches unchanged.
