# Financial exception milestone

Records temporary payment holds, restoration after external settlement, and full external refunds already completed outside the website. No API call to any provider and no money movement. Existing verified payment records remain historical evidence, while an immutable audit event records the exception and the order's paid flag is cleared on hold/refund. All proof, production and final-download checks require both matched original payment and no outstanding exception. The refund is terminal in this workflow; no partial refunds, refund initiation, dispute adjudication or automated provider monitoring. Previously downloaded files cannot be revoked. Separate approval and feature gates default off. Artist and customer histories show the current exception instead of the old payment status; dashboard exposes a hold queue. Synthetic tests exercise hold, restoration, final refund and future download denial. No production commercial flags changed.
