# Artist payment records

Read-only Payments tab reports all-time local evidence grouped by currency and current state, with pending, reconciled, held, refunded, rejected and inconsistent records separate. Verified evidence is classified as reconciled only when it matches the accepted quote and current order state, and is the sole active evidence record. This is not revenue, a provider balance, a cash flow statement, or tax reporting. No currency conversion, fees or tax calculations. Filters and cursor pagination show 25 records per request, and JSON export contains only loaded allowlisted records. No raw provider references, customer identities, or encrypted links. Existing order details remain the only place to perform reconciliation. No money moves; all commercial gates unchanged. Real HTTP fixtures and browser/accessibility coverage added. Corrected a misplaced privacy history browser assertion in the financial exception test.

Session XXI: optional inclusive UTC record-creation date range applies to both summary and record list. The summary still groups all states/currencies in the range, not only the selected row filters. Invalid dates/ranges are rejected. Date edits invalidate loaded results/export until explicitly applied. A failed older-page request retains loaded rows but disables export until retry/refresh. Export requires a private-data confirmation and identifies range, basis and whether pagination is exhausted; this is a live local-record view, not settlement-date accounting or a provider statement.

Payment summary cards now link to their matching currency/state rows. Matching count is derived from the same grouped query and is independent of pagination. Invalid/non-decreasing cursors cannot append inconsistent pages. Export describes pagination exhaustion, first/last page timestamps and explicitly denies a consistent cross-page snapshot; matching classifications may change between reads.
